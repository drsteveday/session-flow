How I work with Claude Code

Session Flow

A reference for how my Claude Code sessions start, save, land and pick up again.

Why I built it

I'm an accidental developer.

I started building apps with Claude with no experience of git or GitHub. I quickly ended up in a mess: work not saved, branches I didn't understand, steps I forgot to do.

I also needed to move fast. My projects are complex, with several streams of work, often on the same code at the same time.

I'm dyslexic and I have ADHD. I forget things and I get distracted. Sometimes I don't touch a project for weeks, and when I come back I need to see exactly where it got to. That's why there's a dashboard: one page showing everything that's open and what stage it's at.

After many months of trial and error, this is what I ended up with.

What it gives me

Two commands to remember: /workon to start, /wrap to stop.
  • Nothing is lostMy memory, history and context are saved automatically, every turn.
  • Git looks after itselfCommits, pushes, branches and merges happen for me.
  • Work in parallelAs many workstreams as I like in one repo, at the same time, each in its own copy so they don't trip over each other.

How it works

One session, start to finish

Each conversation gets a name like om-pipeline-v12: the workstream, then a number. /wrap ends one, /workon om-pipeline-v13 starts the next.

The handoff is what lets a new conversation pick up cold. It says where things are, what's next and what's waiting.

Many workstreams, one repo

Each workstream works in its own copy of the repo (a worktree) on its own branch. Main is locked, so nothing is edited there by accident.

A land merges main into the branch first. If two workstreams clash, the land stops that branch and says why. Main never gets half-merged work.

A workstream can't write on another workstream's board. It drops a note instead, and that workstream's next /workon picks it up.

Quick reference

I typeWhat happens
/workon <name>-v<N>Lands this workstream's finished work in the background, briefs me, then opens a private copy once I say go.
/wrapSaves the session: handoff, ledger entry, board ticks, then marks the work ready or in progress. Work with failing or untested code is never marked ready.
/landShows what's ready across the repo, I pick, it lands. Only I start it.
/quickfix <what>A small fix of a few files: temporary copy, the change, landed, cleaned up. One step.
/dashboardRebuilds the dashboard: every workstream, which repo it's in and where it's up to.
/recall <workstream> <question>Asks the past conversations a question, for example "what did we decide about X".
/repo-healthA snapshot of a repo: its worktrees, branches, unlanded work and open sessions.
/flow-helpShows this quick reference.

The pieces

PieceWhat it is
WorkstreamOne piece of ongoing work, with a short name like om-pipeline. It runs across many conversations.
WorktreeA private copy of the repo for one conversation, on its own branch. Locked to that window while it's open.
HandoffHANDOFF-<name>.md. Where things are now: status, next step, what's pending, standing decisions.
BoardBOARD-<name>.md. The phases and their items, plus an Inbox for new ideas. Created when a plan is approved.
Ledgerdocs/ledger.md. One entry per conversation: what happened. The only history.
RouterHANDOFF.md. Built at every land: one line per workstream with its status. Never edited by hand.
NotesA message from one workstream to another, held outside the repo until the other one's next /workon.
ArchiveA copy of every conversation, grouped by workstream, made every turn. /recall searches it.
DashboardOne local page listing every workstream, its repo and where it's up to.
LandMoving finished work onto main: merge main in, squash into one commit, push, remove the copy.

What runs by itself

WhenWhat
Session startA short report on the repo's state.
Every turnThe work is committed and pushed (in a worktree), and the conversation is copied to the archive.
Before a tool runsMain stays locked; commits carrying a secret or a huge file are blocked.
Before compactingAn emergency save.
75% of context usedOne nudge to wrap soon.
A plan is approvedA reminder to create the board.

Scripts, skills and files

Scripts

The commands keep the judgement. The scripts do the mechanics, so the same steps run the same way every time.

ScriptJob
flow-workon.mjsThe facts for the briefing, then opening or resuming the worktree.
flow-wrap.mjsThe save at the end of /wrap: commit, push, ready or in progress.
flow-land.mjsThe only way work reaches main. One land at a time per repo.
flow-drop.mjsNotes between workstreams: add, list, deliver.
flow-dashboard.mjsBuilds the dashboard.
flow-transcript-sweep.mjsRescues conversations a removed worktree left behind.
flow-worktree-quarantine.mjsCopies a worktree's untracked files to safety before it's removed.
flow-publish-guide.mjsPublishes this page.

Inside a typical repo

Two workstreams, om-pipeline and onboarding, each with one conversation open.

my-app/
├── .claude/
│   ├── flow.yaml                switches Session Flow on
│   ├── branch-state/            ready or in progress, kept on each branch
│   └── worktrees/
│       ├── om-pipeline-v12/     a private copy for one open conversation
│       └── onboarding-v4/
├── docs/
│   ├── ledger.md                one entry per conversation
│   └── notes/                   long notes, linked from a board
├── _handoff-archive/            handoffs of finished workstreams
├── HANDOFF.md                   the router: every workstream's status
├── HANDOFF-om-pipeline.md       where this workstream is now
├── BOARD-om-pipeline.md         its phases and Inbox
├── HANDOFF-onboarding.md
├── BOARD-onboarding.md
└── src/ …                       the app itself
